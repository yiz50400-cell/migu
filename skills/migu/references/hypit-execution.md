# 生成配置与实际执行

视频渠道、多账号切换和固定图片模型见 [视频渠道与图片模型](video-channels.md)。图片一律走客户已配置接口上的 `image2.5flare`。视频可配置多个渠道或多个账号；本节说明共用的配置核对、费用与恢复原则，以及其中使用 Hypit 时的命令。API 视频路线不再依赖 Hypit Runtime。已有可用的 Hypit 安装路径予以保留，不要无故拆掉。

## 配置选择必须来自客户

先读取 local-preferences.md 的配置选择。已有明确长期选择时只读核对后沿用；没有选择才询问。只展示配置名称、用途、模型和凭据是否存在，禁止显示 Key 或完整敏感配置。密钥只记是否存在或长度，不写内容。优先本项目明确引用的渠道和账号；若使用 Hypit，可用 `hypit paths` 及当前 `--help` 定位。没有某个默认目录不代表没有配置；其他客户目录中存在配置也不代表允许使用。

### 必须分别核对图片与视频配置

首轮配置摘要分别列出以下内容，不省略图片模型：

| 类别 | 需要说明 |
|---|---|
| 图片生成/编辑 | 固定为 `image2.5flare`、已配置接口名称或本地路径、凭据存在/缺失/尚未核实（只报存在或长度）、本次用途（如商品参考图、演员、机位或首帧） |
| 视频生成 | 各渠道 id、类型（api 或 hypit）、端点或启动器名称、账号代号、是否启用、凭据存在/缺失/尚未核实、本次镜头生成用途 |

图片使用用户独立配置的 Key/URL 直接调用 `image2.5flare`，不要求位于 Hypit Runtime；使用某个视频渠道也不授权把图片改到 Hypit 或 ChatCut。按实际调用路线读取相应能力与记录回执。图片和视频可能走不同渠道或平台。检查本项目明确引用的配置及用户授权的共享配置，不能因为某个视频渠道没列图片模型就断言本机没有图片配置；也不能自动借用其他客户的配置。只读输出模型/端点标识等必要信息，不输出密钥、签名链接或完整配置。

- 图片模型找到但尚未验证服务可用：如实区分“已找到配置／凭据存在／调用能力未核实”。同时核对 `image2.5flare` 是否支持本次需要的参考图输入或图片编辑，不以只支持文生图的模型冒充图像编辑能力，也不改用其他图片模型。
- 没找到图片配置：明确写“图片模型：未找到本次可用的 image2.5flare 配置”。需要生成商品/演员/首帧时，询问是否现在补配；在补齐前不提交依赖这些参考图的视频生成。
- 本次已有可用图片、无需生图：写“图片生成：本次不使用，直接使用已验收的客户图片”，并解释原因。不为凑齐流程强行生成新图。
- 没有图片配置不能把图片生成交给视频模型，也不能静默换成其他平台或拿图文动画替代。
- 图像与视频分别记录配置选择、确认范围及状态到 Brief。依赖生成图的视频，先验收实际生成图及身份/构图，再提交视频任务。

- 两类都有候选且没有已记录的明确选择时，一次问清：“图片用已配置接口的 image2.5flare 做〔用途〕，视频用〔实际渠道/账号〕做镜头生成；本次沿用这些配置，还是调整其中一项？”提供“全部沿用／调整图片／调整视频渠道或账号”，允许自由补充。例中的渠道名必须来自真实配置。
- 若先前只展示视频渠道、客户回复“沿用现有配置”，该答复仅覆盖已展示的视频配置；保留视频选择，仅补问图片配置。客户明确批准的完整配置同时涵盖两类时不再重复询问。
- 没有可用视频渠道：“还没有可用的视频渠道或账号，要现在配置吗？”提供“现在配置／先做拆解”。已配置 API 视频渠道时，不要把缺少 Hypit Runtime 当成阻塞。
- 用户本轮已明确“用现有配置”、本机偏好已有明确长期选择、或恢复同一制作且记录已有选择，无需重问。改账号/收费端点/模型造成费用或能力变化时再确认相应变化。某个渠道或账号不可用时，保存已完成的分镜和素材，再切换到下一个可用对接。
- 客户拒绝配置则完成无需生成的准备，标为等待配置，不交付假成片。

若实际使用 Hypit，先读取安装的 `hypit/SKILL.md`。若 installation.json 配置了 `hypit_path`，以下 `hypit` 命令均使用该实际启动器（作为独立参数传给进程，不拼接 shell）；没有则从 PATH 查找。配置相关按需读其 `references/environment/profile.md`、`model-and-provider.md`、`distribution.md`；不在这里复制会过时的配置 schema。

只读核对安装与配置可用 `hypit version`、`hypit paths` 和 `hypit auth status <endpoint-instance>`；具体参数以本机帮助为准。凭据“存在”不等于服务可用。必要时做有界的 `doctor` 诊断，不为了探测随手提交生成任务。用户同意配置后，在本机认证流程输入凭据；不把凭据写入 Brief、代码、聊天回显或交付清单。API 视频渠道按其已配置接口的只读检查与提交方式执行，不把 Hypit 命令套到非 Hypit 渠道上。

## 生成计划与费用

写提示词前按当前选用渠道读取相应能力说明；使用 Hypit 时读其 video-direction 和选定模型 Kit，需参考图时读 image-direction，并在编写 Source/Recipe/Run 前按 Hypit references/production/authoring.md 和 runs.md 验证语法。每次从当前能力确认图像/视频输入、最长时长、尺寸、音频支持和输出类型。配置文件存在不代表其旧模型仍可用。图片请求固定为 `image2.5flare`。

使用 Hypit 时，`hypit check run.svrun` 检查；`hypit plan run.svrun` 查看未满足的需求；`hypit pricing run.svrun` 获取当前价格资料。Hypit 不计算整单总价。无论走哪个渠道，都由本流程按实际请求数量、时长/单位及收费账号估算，分开写“估算／已提交／实际账单”，并写入 [预算台账](budget-and-recovery.md)。价格未知则明确未知；不用昨天的积分数或模型计价硬套。

先检查本次会话已有付费约定。未覆盖时只问一次具体范围和估算，分项列出图片模型的参考图数量与费用、视频模型的片段数量/时长与费用，以及需要的托管转写/对齐及重试上限。已有预算覆盖就继续；超出预算、改收费账号或增加额外生成才请求新授权。用户只要求修改本 skill 时，不触发任何生产配置问卷或付费调用。测试与预检不得提交付费生成。

## 提交与恢复

提交前用台账预留预算并绑定幂等键，见 [预算台账与提交恢复](budget-and-recovery.md)。

- 使用 Hypit 时，`hypit build run.svrun` 每次都是新 Build；先保存 Run/计划，再提交一次并立即持久化 Build id。API 渠道按其接口提交，同样先保存请求再提交一次。
- 查询用该渠道的状态接口；使用 Hypit 时用 `hypit status <build-id>`，需要时结合 `activity`、`builds`、`inspect`、`logs`。终端超时/断开不等于远端失败。
- 没拿到任务 id 时先对照提交时间、请求记录和渠道对账恢复。无法确定远端是否接受时保持 `submission_unknown`，不重投。
- 明确失败后修复原因，在剩余授权预算内做有界重试，并使用新的幂等键。无既定重试上限则申请具体增量，不无限换模型试到成功。
- 用当前渠道的合格结果复用机制。仅改字幕/排版不重生视频。
- 导出已完成输出并保留实际命令记录与工具输出；验收文件，而不是仅凭服务返回 succeeded。生成成功不能算整单完成。

若当前渠道或账号不可用，先诊断并保存已完成的分镜和素材，再切换到下一个可用对接。不得擅自切换 Dreamina、ChatCut AI 或纯图文剪辑。没有可用渠道时保留进度并说明阻塞，不交付假成片。
