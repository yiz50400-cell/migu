# 动态素材检查、剪辑与交付

## 素材放行

每条生成视频保存原文件、SHA256、Hypit Build id、输出名、脱敏的真实 inspect/status 输出及其哈希。逐条检查运动、商品身份、手部接触、人物一致性、动作完成区间和连续性，给出实际观察文字。

运行本 skill 的 `scripts/check_handoff.py <project/handoff.json>`。该检查只验证文件、哈希、可解码视频、时长、生成记录关联、已记录审核及必需镜头覆盖；不能自动证明供应商来源真实性或肉眼质量，也不能证明手写 required_shots 已完整覆盖原片；后者必须用独立原片清单逐镜核对。生成记录要与实际 Hypit 工具结果交叉核对，审核记录必须源于实际检查，不能为了通过脚本造字段。

失败素材标记 rejected，部分合格用 usable_in/usable_out。所有必需动态 shot id 都必须有合格区间；缺失返回 Hypit 生成阶段，并遵守剩余预算。不要将 rejected 图像或原片偷放进成片。

## 接入现有剪辑 skill

读取全局 `tiktok-product-video-editor/SKILL.md`。本流程把通过 QA 的生成视频作为客户本次授权的本地输入交付给编辑器。其“本地素材”边界仍成立：编辑阶段不采集、不生成，不调用 ChatCut submit_*，需要补片时返回 Migu 的 Hypit 阶段。

交接 BRIEF.md、REFERENCE-SHOTS.md、SHOT-MAP.md、FIDELITY-REVIEW.md、handoff.json、本地合格素材、参考视频、商品参考、声音决定和目标时长。通过检查后，在成片请求范围内直接继续，无需重复询问是否开始剪辑。

使用编辑器 installation/toolkit 定位规则及本机配置。ChatCut MCP 负责实际镜头时间线，Remotion 负责需要的字幕/文字卡/布局。保留真实 ChatCut project id、底片、工程计划与最终 MP4。无字幕/无卡片的任务不强加包装，单段满足要求时不强制加工。工具不可用就留下具体阻塞和可恢复资料，不能把 FFmpeg 临时拼接描述为 ChatCut 工程。

编辑器默认无 BGM。静音版本静音所有来源；口播版仅保留本次选定口播。原生 AI 口播可作为客户提供的本地口播音轨使用，记录来源并避免再次生成 TTS。

## 最终 QA

先读原片清单，按相同 reference_shot_id 对照参考视频和实际成片，而不只是对照自己改写的计划。在 FIDELITY-REVIEW.md 中记录每镜的参考/成片时间区间、动作阶段、景别、机位/运镜、构图/场景、切点、字幕和叠画差异；静态首尾帧相似不能证明运动过程一致。所有原镜头都要有职责对应，关键过程完整、顺序及节奏保留；必要产品适配属于正常合格范围，不要求另获批准或差异归零。缺步骤、错用法、身份漂移和实质偏离要修复。完整结构复刻不宣称逐帧一致。

剪辑模板不得覆盖原片的布局、节奏和字幕规则；逐镜复刻优先用原片布局，需要时建立最小自定义包装，不因模板方便而新增 CTA 或卖点卡。人物/产品替换、必要产品操作适配、自然动作和语言带来的小幅时序调整，以及既定声音要求，均按主 skill 的边界执行。


按画幅、目标时长、编码、分辨率、帧率、音轨要求做技术检查与完整解码；再检查实际画面。每个镜头检查首/中/尾，并检查完整运动范围；动作、转场和叠画附近加密检查。记录到底是连续播放还是抽帧。

重点检查：侧脸嘴和下巴完整，手和产品不被遮挡，分屏/遮罩不把脸截断，字幕不挡操作，人物和包装不漂移，动作没有因剪切变成未完成。发现裁切先调整布局并复查；原素材本身缺失才回生成阶段。

RENDERED_PENDING_REVIEW 表示已导出但未完成复核，不能当成最终完成。复核报告绑定最终文件 SHA256；再次渲染使旧复核过期。合格才更新 DELIVERY.md 并交付：绝对路径、实际时长/规格、声音、对应素材/工程位置和真实限制。未完成就列缺失镜头和恢复动作，不夸称完成。
