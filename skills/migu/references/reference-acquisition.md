# 按需采集参考

## 选择分支

仅客户明确要求“找爆款／替我选一个 TikTok 参考”时启动搜索。商品图片加“复刻”却没有参考，也没有要求寻找时，询问其提供参考还是需要代找；可先做商品分析。客户只给商品并要原创视频可直接规划原创。

客户给本地视频：保留原文件，记录 SHA256，直接检查全片。
客户给具体链接：只解析/下载该条视频到项目 references/。短链接先核对实际解析目标。下载失败请客户提供可读取文件，不能悄悄换片。用户提供视频无默认 25 秒上限。

## 默认采集项目

读取 installation.json 的 collection_root（新部署默认指向随仓库提供的 toolkits/collector），先读该项目存在的 AGENTS.md 及说明；只调用发现/下载能力，不启动 unattended 全生产、定时器或批量发布。

当前适配的项目入口（运行前核对文件及签名）：
- `workflow/unattended/evil_discovery.py` 的 `probe_evil`、`try_evil_discovery`：从本机 Evil 服务找 TikTok 页面链接。请求中传当前产品，form_hints 中传本次目标语言查询词，限制候选数量和查询数。返回 degraded 时保存原因。
- `workflow/collection/collector.py` 的 `resolve_video(url)`：用 yt-dlp 获取时长、标题、作者、可见互动数据；`download_video(candidate, output_dir)`：下载指定候选，candidate 至少含 id/source_url。运行项目现有 Python 环境，遵守当前实际函数签名。
- 需要完整采集证据报告时使用该模块的 `collect`，它可能有同 SKU/实拍用途分类。复刻用“结构参考”，不可把非本品视频登记成可直接剪辑的本品实拍。

本项目中 Evil 负责找链接，yt-dlp 负责解析与下载。它们不是 AI 生成器。不要把这里的适配方式说成 Evil 上游全部能力；也不要认为 yt-dlp 能自动选出带货爆款。

服务不可用时先给出真实原因。若该项目允许降级搜索，就以可用搜索/浏览工具寻找官方 TikTok 原链接，再交 yt-dlp；标明降级路线。若安装/启动 Docker、Evil 或准备下载环境需要额外操作，说明具体动作并取得该动作所需授权。仅读取客户给的单条链接通常无需 Evil。

优先既有采集项目。该项目未安装或不可用时，不默默换工具；说明情况，可按已授权替代方式使用已安装 yt-dlp 或 Hypit download。`hypit download prepare` 会准备环境，不当只读命令运行。Migu 不预装 Docker 或自动复制浏览器 Cookie。

## 找参考的默认筛选

- 默认先取最多 8 个去重候选，优先相同商品或相同演示动作、目标市场和语言、15–25 秒且动作完整的实拍参考。
- 先用元数据筛时长，再下载少量最相关候选。元数据缺时长需下载/检查后确认，不猜。
- 保存 source_url、作者、观察时间、发布时间（如可见）、duration、views/likes/comments（如可见）和来源证据。未知就是未知；播放量不是销量，不能承诺未来会爆。
- 基于真实可见表现、动作可复刻性、商品匹配、镜头数量和预计生成成本选主参考，不仅凭标题含“爆款”。
- 没有合格 15–25 秒候选时如实说明。继续有界搜索或询问是否接受较长参考，不偷偷截断动作、不伪造热度。
- 参考只用于拆解与有依据的生成指导；是否作为模型的视频输入按 Hypit 的视频参考规则及本次授权决定，不默认把竞品片段拼进成片。
