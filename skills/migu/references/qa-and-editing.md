# 检查与剪辑交接

提交每个真实分镜的视频前，先运行 `scripts/check_handoff.py --ready-for-video <project/handoff.json>`（或含分镜与场景参考图的计划清单）：没有对应该镜景别的场景参考图、或主参考仍是共用人物/产品图时不得提交。该检查不提交付费生成。素材齐备后运行 `scripts/check_handoff.py <project/handoff.json>`。完整交接检查验证文件、哈希、可解码视频、请求时长/可用区间/成片时长、每镜场景参考图、生成记录关联、已记录审核、真实分镜数量（通常最多 6 个；7–19 个需书面理由；20 个及以上拒绝）以及（若提供 delivery）验收项。它不能自动证明供应商来源真实性或肉眼质量，也不能单靠脚本证明结构、节奏和重点已经保留；后者必须对照原片和计划分镜核对。生成记录要与实际渠道回执交叉核对，审核记录必须源于实际检查，不能为了通过脚本造字段。生成成功不能算完成。

失败素材标记 rejected，部分合格用 `in`/`out` 作为可用区间，并同时记录 `requested_duration` 与 `output_duration`。所有必需动态 shot id 都必须有合格区间；缺失返回生成阶段，并遵守剩余预算。不要将 rejected 图像或原片偷放进成片。

调用剪辑 skill 前，把通过检查的本地生成视频、Brief、SHOT-MAP 和本清单一并交给它。采集和生成由本流程承担；剪辑模块只处理这些已授权的本地素材，不为完成剪辑再去搜索或生成。单段生成结果已能作为完整成片时，直接进入最终验收，不强行再渲染。

剪辑模板不得覆盖原片的布局、节奏和字幕规则；优先用原片布局保留结构、节奏和重点，需要时建立最小自定义包装，不因模板方便而新增 CTA 或卖点卡。复刻画面里需要复刻的文字也要复刻。人物/产品替换、必要产品操作适配、自然动作和语言带来的小幅时序调整，以及既定声音要求，均按主 skill 的边界执行。

按画幅、目标时长、编码、分辨率、帧率、音轨要求做技术检查与完整解码；再检查实际画面。每个镜头检查首/中/尾，并检查完整运动范围；动作、转场和叠画附近加密检查。记录到底是连续播放还是抽帧。

另核对每段实际素材文件、源区间和画面内容，发现相同素材重复用于不同镜头时按本机偏好处理。检查原片的结构、节奏和重点是否保留，不以只修正重复或只变速证明复刻合格，也不以“已经生成成功”代替验收。

重点检查：

- 实际切镜是否与计划分镜一致
- 穿帮：侧脸嘴和下巴完整，手和产品不被遮挡，分屏/遮罩不把脸截断，人物和包装不漂移，动作没有因剪切变成未完成
- 对应国家语言：口播、字幕和屏幕文字使用已确认的目标语言
- 视频包装：复刻画面里需要复刻的文字也要复刻；字幕不挡操作
- 字幕本身是否正确、同步
- 最终导出文件可完整解码，时长与记录的成片时长相符

发现裁切先调整布局并复查；原素材本身缺失才回生成阶段。

`RENDERED_PENDING_REVIEW` 表示已导出但未完成复核，不能当成最终完成。复核报告绑定最终文件 SHA256，并填写 delivery.acceptance 中的切镜、穿帮、对应国家语言、视频包装、字幕和最终导出，verdict 必须为 pass。再次渲染使旧复核过期。合格才更新 DELIVERY.md 并交付：绝对路径、实际时长/规格、声音、对应素材/工程位置和真实限制。未完成就列缺失镜头和恢复动作，不夸称完成。
