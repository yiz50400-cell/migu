# Hypit 配置与实际生成

## 配置选择必须来自客户

先发现再询问，只展示配置名称、用途、模型和凭据是否存在，禁止显示 Key 或完整敏感配置。优先本项目明确引用的 Runtime；用 `hypit paths` 及当前 `--help` 定位。没有某个默认目录不代表没有配置；其他客户目录中存在配置也不代表允许使用。

### 必须分别核对图片与视频配置

首轮配置摘要分别列出以下两行，不省略图片模型：

| 类别 | 需要说明 |
|---|---|
| 图片生成/编辑 | 实际模型名、Runtime/Endpoint 名称或本地路径、凭据存在/缺失/尚未核实、本次用途（如商品参考图、演员、机位或首帧） |
| 视频生成 | 实际模型名、Runtime/Endpoint 名称或本地路径、凭据存在/缺失/尚未核实、本次镜头生成用途 |

图片和视频可能在不同 Runtime 中。检查本项目明确引用的配置及用户授权的共享配置，不能因为视频 Runtime 没列图片模型就断言本机没有图片配置；也不能自动借用其他客户的 Runtime。只读输出模型/端点标识等必要信息，不输出密钥、签名链接或完整配置。

- 图片模型找到但尚未验证服务可用：如实区分“已找到配置／凭据存在／调用能力未核实”。同时核对所选模型是否支持本次需要的参考图输入或图片编辑，不以只支持文生图的模型冒充图像编辑能力。
- 没找到图片配置：明确写“图片模型：未找到本次可用配置”。需要生成商品/演员/首帧时，询问是否现在补配；在补齐前不提交依赖这些参考图的视频生成。
- 本次已有可用图片、无需生图：写“图片生成：本次不使用，直接使用已验收的客户图片”，并解释原因。不为凑齐流程强行生成新图。
- 没有图片配置不能把图片生成交给视频模型，也不能静默换成其他平台或拿图文动画替代。
- 图像与视频分别记录配置选择、确认范围及状态到 Brief。依赖生成图的视频，先验收实际生成图及身份/构图，再提交视频任务。

- 两类都有候选时，一次问清：“图片用〔实际图片模型〕做〔用途〕，视频用〔实际视频模型〕做镜头生成；本次沿用这两套配置，还是调整其中一项？”提供“全部沿用／调整图片／调整视频”，允许自由补充。例中的模型名必须来自真实配置，不写死历史任务模型。
- 若先前只展示视频模型、客户回复“沿用现有配置”，该答复仅覆盖已展示的视频配置；保留视频选择，仅补问图片配置。客户明确批准的完整配置同时涵盖两类时不再重复询问。
- 没有可用配置：“还没有可用的 Hypit 配置，要现在配置吗？”提供“现在配置／先做拆解”。
- 用户本轮已明确“用现有配置”、或恢复同一制作且记录已有选择，无需重问。改账号/收费端点/模型造成费用或能力变化时再确认相应变化。
- 客户拒绝配置则完成无需生成的准备，标为等待配置，不交付假成片。

先读取安装的 `hypit/SKILL.md`。配置相关按需读其 `references/environment/profile.md`、`model-and-provider.md`、`distribution.md`；不在这里复制会过时的配置 schema。

只读核对安装与配置可用 `hypit version`、`hypit paths` 和 `hypit auth status <endpoint-instance>`；具体参数以本机帮助为准。凭据“存在”不等于服务可用。必要时做有界的 `doctor` 诊断，不为了探测随手提交生成任务。用户同意配置后，在本机认证流程输入凭据；不把凭据写入 Brief、代码、聊天回显或交付清单。

## 生成计划与费用

写提示词前读 Hypit 的 video-direction 和选定模型 Kit；需参考图时读 image-direction。编写 Source/Recipe/Run 前按 Hypit references/production/authoring.md 和 runs.md 验证语法。每次从当前能力确认图像/视频输入、最长时长、尺寸、音频支持和输出类型。配置文件存在不代表其旧模型仍可用。

`hypit check run.svrun` 检查；`hypit plan run.svrun` 查看未满足的需求；`hypit pricing run.svrun` 获取当前价格资料。Hypit 不计算整单总价，由本流程按实际请求数量、时长/单位及收费账号估算，分开写“估算／已提交／实际账单”。价格未知则明确未知；不用昨天的积分数或模型计价硬套。

先检查本次会话已有付费约定。未覆盖时只问一次具体范围和估算，分项列出图片模型的参考图数量与费用、视频模型的片段数量/时长与费用，以及需要的托管转写/对齐及重试上限。已有预算覆盖就继续；超出预算、改收费账号或增加额外生成才请求新授权。用户只要求修改本 skill 时，不触发任何生产配置问卷或付费调用。

## 提交与恢复

- `hypit build run.svrun` 每次都是新 Build；先保存 Run/计划，再提交一次并立即持久化 Build id。
- 查询用 `hypit status <build-id>`，需要时结合 `activity`、`builds`、`inspect`、`logs`。终端超时/断开不等于远端失败。
- 没拿到 id 时先用 activity/builds 对照提交时间、Run、任务记录恢复。无法确定远端是否接受时保持 SUBMISSION_UNKNOWN，不重投。
- 明确失败后修复原因，在剩余授权预算内做有界重试。无既定重试上限则申请具体增量，不无限换模型试到成功。
- 用当前 Run 的 Candidates/build-record/satisfy 机制复用合格结果。仅改字幕/排版不重生视频。
- `hypit get <build-id> --output <name> --to <path>` 导出已完成输出。保留实际命令记录与工具输出；验收文件，而不是仅凭服务返回 succeeded。

若当前工具不可用，先诊断并保存已完成的分镜和素材。不得擅自切换 Dreamina、ChatCut AI 或纯图文剪辑。
