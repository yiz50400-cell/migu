# Local Product Video Editing

## Toolkit location

Resolve the editing toolkit from the current Migu handoff's `editor_toolkit_root`, this skill's local `installation.json` field `toolkit_root`, or the explicitly supplied toolkit directory. Verify the location before executing commands; if unset, ask for or locate the existing installation. Never assume the customer's media project is the toolkit. Resolve README.md, DEPLOYMENT.md, docs/, config/, root scripts/ and remotion/ against the verified toolkit; resolve skill-local references and helper scripts against this skill. Use the toolkit's prepared Python environment and absolute customer input/output paths. A copy of this skill does not install the toolkit, ChatCut MCP or Remotion. Keep all customer media and generated output in the customer's project.

The default customer workflow uses Codex Desktop, a signed-in ChatCut Desktop, and Remotion. First read the project's README.md, DEPLOYMENT.md, and docs/local-editing-workflow.md. Supported markets are MX/es-MX, BR/pt-BR, ID/id-ID, and PH (choose the task language according to the customer's request). Batch size: 1–100 videos.

## Operating Contract

Use local videos and local references supplied by the customer, including local AI videos generated upstream within the same authorized production. When invoked by `migu`, read its Brief, shot map, generation evidence and QA handoff, verify source hashes and usable ranges, and continue the already requested edit without another start confirmation. Product links or images cannot replace required moving demonstration footage. The editing stage does not search, download, install collection components or generate video; if footage is insufficient, record the specific missing actions, angles or duration and return that gap to the upstream Migu/Hypit stage when available, otherwise request additional local material. Do not substitute a photo slideshow for an AI remake.

Complete production directly within the authorized scope by default. Do not request step-by-step approval of Chinese scripts, voices, or samples unless the customer explicitly asks for an interactive refinement workflow. Internal review is not customer approval; never invent approvers, approval text, or listening evidence. Do not create background tasks or agents without authorization.

All final videos must have no background music: mute all source footage for silent videos; for narrated videos, retain only the narration track. Edit shots through ChatCut MCP and create captions and visual packaging with local Remotion. Do not use in-app AI, submit_* generation tools, or UI automation. Reuse accepted native AI speech as a local narration track when the brief requires it; use locally configured TTS only for requested post-production narration; editing local footage does not imply that every service operates offline.

## Workflow

1. Confirm local paths, product, market, quantity, and style; reuse details already clear from the conversation. Import footage and bind its actual SHA256 hashes while preserving the original files.
2. Inspect usable shots, product consistency, clarity, watermarks, continuous action boundaries, and actual duration. Select suitable clips for the hook, demonstration, action, result, and CTA without forcing every clip into the final video.
3. Read docs/template-guided-editing.md, run `package_remotion.py templates`, and inspect the actual previews. Choose a template suited to the footage and style: classic (clean product), kinetic-product (technology highlights), comparison-review (sequential A/B), step-guide (steps), unboxing-reveal (unboxing), or minimal-luxe (minimal premium). Comparison cards alternate A/B by odd/even position; each step card represents one step. Unboxing requires actual unboxing footage; animation is not evidence of product facts. Plan each video's shots, distinct creative choices, and duration. Narration must contain only verifiable claims; consult references/tiktok-shop-video-compliance.md. Internally proofread the Chinese draft and target-language copy. Request incremental customer approval only in interactive refinement mode.
4. Prepare or reuse the selected narration audio and its matching SRT. Check local language, voice, duration, pauses, and synchronization. Shorten overly long scripts rather than filling time with frozen frames. Silent versions do not need fabricated narration subtitles.
5. Once footage and any requested copy/SRT are ready, use `package_remotion.py plan` to save the shot/copy/caption/animation alignment table with real asset_id values, source times, output times, visual observations, and selling points. Verify timeline continuity and product facts. First check ChatCut MCP connectivity with the read-only list_projects call. Create a new project or duplicate an existing one, explicitly set target_project, and use the current tool schemas to import local media and edit the timeline, captions, transitions, and native effects. Retain the project ID; do not overwrite a customer's existing project with the same name.
6. Follow docs/chatcut-remotion-workflow.md to export a clean base video without burned-in captions and, when captions are requested, a separate SRT from ChatCut. Fill the plan-generated draft with the real chatcut_project_id and video_path, retaining template_id and storyboard_path. Use package_remotion.py for the requested titles, cards, captions or CTA; skip additions absent from the brief/reference and skip redundant packaging for a clean export that already satisfies the request. Keep shot order and narration timing consistent with the base video. Preserve logs and outstanding work if packaging fails.
7. Preview action continuity, subject framing (including side-profile mouth/chin, hands and product throughout overlays), caption readability and safe areas, and confirm that unrequested source sound is muted and only the selected narration remains in narrated versions. Export an actual MP4 and record its project and path. Do not report a finished video before export completes.
8. Independently check the requested output specifications (default H.264, 1080x1920 and yuv420p for vertical TikTok delivery), target frame rate, planned duration, frozen frames, and audio tracks. Visually review each final video; listen to each narrated version and verify caption synchronization. Technical QA does not replace visual acceptance.
9. Use scripts/deliver_video.py to register actual final videos, source ownership, subtitles, Chinese delivery notes, and genuine review evidence. Update progress using the actual number of successful deliveries. Preserve evidence and outstanding work on failure; do not overwrite successful outputs. Deliver clickable absolute local file paths.

## Compatibility and Recovery

scripts/workflow.py supports job creation, import, and analysis/plan registration. Its run command is an explicit debugging/interactive pipeline that may require genuine approval; it is not an automatic ChatCut renderer. Keep the legacy tk-ops-workspace FFmpeg tools for debugging and compatibility, and do not present their output as a native ChatCut project. When resuming, verify source hashes and delivered ordinals first; do not recompute or overwrite verified results. The customer handles uploading and publishing manually.

Use Remotion refinement for layout, captions, cards, and animation. Return to ChatCut for shot pacing changes, then export and package again. Do not describe a composited MP4 as an automatically recoverable multitrack project. Fill delivery manifest templates with genuine review results before registering delivery.
